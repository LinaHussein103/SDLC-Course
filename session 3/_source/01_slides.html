Foundations

What is UI?

User Interface — everything a person sees, hears and touches to operate a product: the visible layer between the user and the system.

1
Visual elements — icons, images, cards, colour blocks
2
Buttons, forms & navigation — the controls people operate
3
Typography & colour — font, size, weight, palette, contrast
4
Layout & visual hierarchy — what the eye sees first, second, third
5
Interactive elements — toggles, tabs, states (pressed, disabled, loading)

Think of UI as the “what”: the screen-level decisions you could point at in a screenshot.

What is UX?

User Experience — how it feels to reach a goal with a product, from first intention to final outcome. It includes the screens, but also timing, wording, effort, errors and what happens off-screen.

Impact

Why UI/UX matters

Task completion

Can people actually finish what they came to do?

User satisfaction

Will they choose to come back?

Accessibility

Can people with disabilities use it at all?

Error rates

Confusing UI creates wrong data and support tickets.

Development cost

A fix in a sketch takes minutes; after release it takes sprints.

Customer retention

Users leave products that waste their time.

Business success

Adoption, reputation and cost all depend on whether real users succeed.

Codeflow PSUT · UI/UX Design09
Thinking like a user

Understanding user goals

A student wants to know one thing: “Does the library have this book?” Developers often design around what the system needs first.

System-first flow
Open→ Sign in→ Dashboard→ Search→ Answer

The answer arrives last. A guest, a forgotten password, or a slow login blocks a simple question.

Goal-first flow
Open→ Search→ Answer→ Sign in only to reserve

The answer comes first. Identity is requested only when it becomes necessary.

Progressive disclosure

Reveal complexity (forms, options, sign-in) only when the user reaches the step that needs it.

Remove unnecessary steps

Every extra screen between the user and their goal is a chance to give up.

But: protect what must be protected

Authentication is still required before protected actions — reserving, viewing personal loans or fines.

ASK AT EVERY STEP “What is the least the user must give us right now — and why do we need it here?”

Codeflow PSUT · UI/UX Design11
Design artefacts

What is a user flow?

A diagram of the steps and decisions a user goes through to complete one goal. It helps teams spot missing screens, dead ends and unnecessary steps — before anything is drawn in detail.

User flow

What the user does, step by step, toward a goal. Screens + decisions.

Database schema

How data is stored: tables, keys and relationships. No user steps.

Architecture diagram

How system components connect: app, API, database, services.

Codeflow PSUT · UI/UX Design12
Design artefacts

What is a wireframe?

A simplified, usually grayscale blueprint of a screen. It shows structure, layout, content hierarchy and navigation — deliberately leaving out colour, imagery and polish.

Why wireframe before development?

Cheap to change

Move a box, not a component tree.

Aligns the team

Devs, designers & clients see the same plan.

Exposes gaps

Missing requirements and states show up early.

Testable early

Users can react before code exists.

Industry toolkit

Industry design tools — and where they fit

✎
Pen & paper

Rapid sketching, crazy-8s, paper prototypes. No learning curve.

◫
FigJam

Online whiteboard for user flows, journey maps and team workshops.

◩
Figma

Collaborative wireframes, mockups, prototypes and developer hand-off.

▦
Design systems

Shared rules: colours, type, spacing, patterns. e.g. Material Design, Apple HIG.

❒
Component libraries

Reusable coded parts that match the design system: buttons, inputs, cards.

◎
Usability testing

Moderated sessions, unmoderated tools (e.g. Maze), screen recording & surveys.

A typical team week
Sketch 6 ideas on paper → map the chosen flow in FigJam → wireframe in Figma using the team’s design system → link a clickable prototype → test with 5 users → engineers build with the component library.

Mobile-first

Why mobile-first?

Design for the smallest, most constrained screen first, then enhance for larger ones. Constraints force you to decide what truly matters.

Limited screen space

No room for “nice to have”.

Content prioritisation

The primary task goes on top.

Touch interactions

Fingers, not precise mouse pointers.

Thumb-friendly navigation

Key actions within easy reach.

Responsive layouts

One design adapts to every width.

Progressive enhancement

Add columns & shortcuts as space grows.

Case-study hypothesis: we assume most students will use the library system on their phones. This is not a verified statistic about PSUT students — a real team would confirm it with surveys or analytics.

Final takeaway

Good UI/UX is not just about making software look good.

01Make the correct actions easy
02Make the system’s behaviour understandable
03Make mistakes preventable or recoverable

Justify every design decision with user needs, requirements and usability evidence — not personal taste.
